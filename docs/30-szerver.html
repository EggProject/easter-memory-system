02Storage provider

A tár mögött egy szűk interfész van, hogy a fájlrendszer ne szivárogjon szét a kódban. Ez teszi lehetővé, hogy a tár később máshol legyen — de a v1-ben egy implementáció készül, a fájlrendszeres.

interface StorageProvider {
  read(path: string): Promise<string>;
  write(path: string, content: string): Promise<void>;   // atomi csere
  move(from: string, to: string): Promise<void>;
  list(prefix: string): Promise<string[]>;
  stat(path: string): Promise<{ size: number; commitIso: string } | null>;
  commit(message: string, paths: string[]): Promise<void>;
}
SzabályMiért
Az írás atomi csere: ideiglenes fájl, majd átnevezésFélbeszakadt írás nem hagyhat csonka fájlt
Nincs delete a felületenAz invariáns így nem megsérthető — csak move van, archívumba (I3)
A stat a git commit dátumát adja, nem az mtime-otAz mtime-ot egy clone felülírja, tehát nem hordoz információt

06Az index

Egyetlen SQLite fájl a tárON KÍVÜL, bun:sqlite-tal. A beépített FTS5 elérhető, tehát nem kell natív modul.

CREATE TABLE topic(
  id            TEXT PRIMARY KEY,
  path          TEXT UNIQUE NOT NULL,
  title         TEXT NOT NULL,
  scope         TEXT,                 -- vagy category, a kettőből egy
  category      TEXT,
  body          TEXT NOT NULL,        -- frontmatter nélkül
  stems         TEXT NOT NULL,        -- derivált: magyar + angol tövek
  content_hash  TEXT NOT NULL,
  commit_iso    TEXT,                 -- git-ből, nem mtime; amíg nincs commit: az updated_at
  pinned        INTEGER NOT NULL DEFAULT 0,
  status        TEXT NOT NULL DEFAULT 'active'
);

CREATE TABLE fact(
  id            TEXT PRIMARY KEY,
  topic_id      TEXT NOT NULL REFERENCES topic(id),
  place_key     TEXT NOT NULL,        -- a scope útvonala VAGY 'cat:'
  seq           INTEGER NOT NULL,
  subject       TEXT NOT NULL,
  predicate     TEXT NOT NULL,
  status        TEXT NOT NULL,
  evidence      TEXT NOT NULL,
  created_at    TEXT NOT NULL,
  expired_at    TEXT,                 -- rendszer-idő: mikor tudtuk meg
  valid_from    TEXT,                 -- világ-idő, opcionális
  valid_until   TEXT,                 -- világ-idő, opcionális
  supersedes    TEXT,
  superseded_by TEXT,
  retract_reason TEXT,                -- kötelező, ha status = 'retracted'
  session       TEXT NOT NULL,
  src           TEXT NOT NULL
);
CREATE UNIQUE INDEX fact_key_active
  ON fact(place_key, subject, predicate)
  WHERE status = 'active';           -- a determinisztikus ellentmondás-védelem

CREATE TABLE vec(                    -- számsorok, TÉMA szinten
  topic_id      TEXT PRIMARY KEY REFERENCES topic(id),
  model         TEXT NOT NULL,       -- melyik modell készítette

CREATE TABLE usage(                  -- telemetria — SOHA nem a markdownban

07Keresés és rangsorolás

A lekérdezés

SELECT t.id, t.path, t.title, t.commit_iso, t.pinned,
       bm25(fts, 8.0, 1.0, 0.7) AS raw,
       snippet(fts, 1, '«', '»', ' … ', 48) AS snip
FROM fts JOIN topic t ON t.rowid = fts.rowid
WHERE fts MATCH :expr
  AND t.status IN ('active', 'suspect')        -- a suspect kiadható, csak jelölve
  AND (:includeArchived OR t.status != 'archived')
  AND (t.scope IN (:visible) OR t.category IN (:visibleCats))
ORDER BY raw
LIMIT 50;

A :expr felépítése a magyar miatt nem triviális. A mért működő minta minden szóra:

(<szó> OR <szó>* OR stems:<tő>*)     — és a szavak között AND
VáltozatSzótári alakraRagozott alakra
Csak tövezés0,8710,863
Csak prefix1,0000,323
A három együtt1,0000,885
Mit indexelünk a törzsből

Az FTS-be és a számsorba csak az aktív és a gyanús tények szövege kerül. Az érvénytelenített és visszavont tények a fájlban maradnak — a felület mutatja is őket halványan, mert az információ —, de az indexelt törzsből kimaradnak. Így nem kell tény-szintű szűrés a lekérdezésben, és mégsem jön vissza találatként egy már megcáfolt állítás.

A pontszám

L̂ᵢ = (Lᵢ − min L) / (max L − min L)      ahol Lᵢ = −bm25ᵢ      (min-max a jelölteken)
Ŝᵢ = (Sᵢ − min S) / (max S − min S)      ahol Sᵢ = koszinusz-hasonlóság

score(i) = 0.60 · L̂ᵢ
         + 0.40 · Ŝᵢ
         + 0.50 · pinnedᵢ
         + 0.25 · scopeKözelségᵢ
         + 0.20 · log1p(hitsᵢ) / log1p(50)

rendezés: score DESC, majd commit_iso DESC, majd path ASC
TagSúlyMiért ennyi
Szöveges egyezés0,60A pontos szó a legerősebb jel, ha van
Jelentés-hasonlóság0,40Ez hozza be azt, amit más szavakkal kerestek
Kitűzött0,50Explicit emberi szándék minden heurisztikánál erősebb
Scope-közelség0,25A saját projekt tudása előbbre való az orgénál
Korábbi használat0,20Logaritmikusan telítve, hogy egy sokszor olvasott fájl ne uralja a listát
Kor0,00Nincs benne. Mérés szerint az idő mint előrejelző AUC ≈ 0,51 — érmefeldobás. Csak döntetlennél számít

Ami a pontszám után jön

  1. Hasonlók kiejtése — ha egy találat háromgrammos hasonlósága egy már kiválasztottal 0,85 fölött van, kiesik.
  2. Vágás — alapból 8 találat, legfeljebb 25.
  3. Küszöb — abszolút értéken, nem a normalizálton: az a találat esik ki, aminek a nyers BM25-je a leggyengébb sávba esik és a koszinusz-hasonlósága 0,25 alatt van. A normalizált pontszámra tett küszöb matematikailag értelmetlen lenne, mert a legjobb jelölt definíció szerint mindig 1,0-t kap — akkor is, ha abszolút értelemben zaj.
  4. Elfajult eset — ha a jelölt-halmazon max = min, a normalizált érték minden elemre 1,0, és a rangsort a maradék tagok döntik el. Nullával osztás nincs.
  5. Nulla találat esetén a válasz üres lista és a látható források fája. Az agent így tud navigálni. Kitalált találat nincs.
  6. A használati számláló csak akkor nő, ha az agent ténylegesen le is kérte a téma tartalmát — nem attól, hogy megjelent a listában. Enélkül a számláló önmagát erősítené.
