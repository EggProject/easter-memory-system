Miért lapos a memory könyvtár

Mély könyvtárfa rontja a részleges szerkesztést és a navigációt. Egy csomóponton belül a fájlnév a téma: build-tooling.md, deploy.md, ugyfel-kontaktok.md. Ha egy fájl túl nagy lesz, ketté kell vágni — nem alkönyvtárba tenni.

refs — a horgonyok

Ez a rendszer legerősebb elavulás-jelzője, és nem kell hozzá modell. Egy kutatási mérés szerint a legnépszerűbb GitHub projektek több mint negyedében van olyan dokumentációs hivatkozás, ami már nem létezik — a horgony pontosan ezt fogja meg.

08Grantek

Alapból egy projekt nem lát testvért. A grant ez alóli nevesített kivétel, és a tár konfigurációjában él, hogy egy helyen látszódjon az összes.

# easter.config.yaml részlet
grants:
  - id: grant_01J9XW9P
    from: egg/pctrade/webshop-frontend
    to:   egg/pctrade/webshop-backend
    direction: both            # both | one_way
    reason: "Ugyanaz a termék két fele, közös API-szerződés"
    created_by: user:eggprojec
    created_at: "2026-08-19T10:00:00Z"
    expires_at: null           # opcionális lejárat
SzabályMiért
A grant csak azonos szülő alatti csomópontok között adhatóKét ügyfél közötti átjárás nem kivétel, hanem hiba

09A láthatóság algoritmusa

Ez a rendszer legfontosabb függvénye. Bemenete egy hívó scope-ja, kimenete azoknak a helyeknek a halmaza, ahonnan találat érkezhet.

function visibleSources(caller: ScopePath): Source[] {
  const out: Source[] = [];

  // 1 — a saját ág, felfelé a gyökérig
  for (let n = node(caller); n; n = n.parent) out.push(n);

  // 2 — minden kategória, aminek a láthatósága ezt megengedi
  for (const c of categories()) {
    if (c.visibility === 'all') out.push(c);
    else if (c.listed.includes(caller)) out.push(c);
  }

  // 3 — nevesített grantek, csak azonos szülő alatt, nem tranzitívan
  for (const g of grants()) {
    if (g.expired) continue;
    if (g.from === caller) out.push(node(g.to));
    else if (g.direction === 'both' && g.to === caller) out.push(node(g.from));
  }

  return out;   // minden más: nem látható
}
Amit ez a függvény soha nem tesz
  • Nem megy lefelé a fában. Egy client szintű hívó nem látja a projektek memóriáit — azok részletek, nem összegzés.
  • Nem lép át másik ügyfélhez, grant-tel sem.
  • Nem következtet. Ha egy hely nincs a listában, onnan nem jön találat, akkor sem, ha a keresés egyébként tökéletes egyezést találna.
Tesztelési követelmény

Erre a függvényre tulajdonság-alapú teszt kell, nem példateszt: generált fákon és grant-halmazokon kell igazolni, hogy két különböző client ág között soha, semmilyen konfigurációval nem keletkezik átjárás. A spec 60 ezt elfogadási kritériumként rögzíti.
