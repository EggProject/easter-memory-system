Ha a felismerés nem egyértelmű

Ha a szerver több csomópontot talál, vagy egyet sem, akkor SCOPE_UNKNOWN hibát ad, és felsorolja a szóba jövő jelölteket. Nem választ helyetted. Egy rossz automatikus párosítás azt jelentené, hogy az egyik ügyfél memóriája a másik session-ébe kerül — ez pontosan az a hiba, amit a rendszer meg akar előzni.

03Hook réteg

A Claude Code hook-felülete a legrészletesebb, ezért az a referencia. A telepítő a settings.json-ba írja be, és mindössze két eseményre kell rákötni.

SessionStart — az index betöltése

{
  "hooks": {
    "SessionStart": [
      { "matcher": "startup|resume|clear|compact",
        "hooks": [
          { "type": "command",
            "command": "easter",
            "args": ["hook", "session-start"],
            "timeout": 20,
            "statusMessage": "Memória betöltése…" }
        ] }
    ]
  }
}

A hook a stdin-en megkapja a session adatait, lekéri a szervertől az indexet, és a válaszában adja vissza:

{
  "hookSpecificOutput": {
    "hookEventName": "SessionStart",
    "additionalContext": "Elérhető memória ehhez a projekthez (egg/pctrade/webshop):\n\n· Build tooling — 7 tény, frissítve 2026-08-18\n· Deploy folyamat — 12 tény, frissítve 2026-08-02\n· [tech] Angular signal minták — 23 tény\n\nA részletekért használd a memory_search és memory_read toolt."
  }
}
MegkötésÉrtékKövetkezmény a tervre
Beszúrható méret10 000 karakterAz index kerete 8 000 — a maradék a keretszövegé
Ha túllépiA kliens fájlba írja, és csak az útvonalat adja átEzért kell a szervernek magának korlátoznia
Újrafutásresume és compact eseménynél is lefutTömörítés után a memória-index visszakerül a kontextusba

SessionEnd — az extrakció elindítása

{
  "hooks": {
    "SessionEnd": [
      { "hooks": [
          { "type": "command", "command": "easter",
            "args": ["hook", "session-end"],
            "timeout": 30 } ] }
    ]
  }
}
Két buktató, amit a terv figyelembe vesz
  • A SessionEnd hooknak alapból nagyon rövid ideje van. Explicit timeout kell, különben a rendszer megöli, mielőtt bármit tenne.
  • A hook nem dolgozza fel maga a beszélgetést. A POST /v1/sessions/:id/end végpontnak átadja azt a néhány strukturált mezőt, amit a kliens amúgy is ad — összefoglaló, záró üzenet, módosított fájlok —, és azonnal visszatér. Az extrakció a szerveren fut tovább.

Protokoll-verzió

A cél a 2026-07-28 revízió. Ez a kiadás jelentősen átírta a protokollt: megszűnt a session-fogalom és a kezdeti kézfogás, kötelező lett egy felderítő hívás, és a szerver nem kezdeményezhet kérést a kliens felé. A mérés szerint a jelenlegi Claude Code ezt a revíziót beszéli, és szabályosan vissza is lép a régebbire, ha a szerver nem tudja. A hivatalos TypeScript SDK v2-es sora ehhez a revízióhoz készült, és a függősége mindössze egyetlen külső csomag — ez illeszkedik a minimális függőség céljához.

06Session végi extrakció

Mit kap a modell, és mit nem

Bemenet

  • A session utolsó összefoglalója és a záró üzenet
  • A módosított fájlok listája
  • A cél scope kategóriáinak leírása

Amit szándékosan nem kap

  • A session elején beszúrt memória-index
  • Bármi, ami korábban derived forrásból jött
  • Tool-kimenetek nyers tartalma — ezek külső eredetűek, tehát nem lehetnek tényforrások
Miért nem a beszélgetés naplófájljából dolgozunk

A kliensek naplóformátuma belső, verziónként változik, és a dokumentáció maga figyelmeztet, hogy a közvetlen feldolgozás bármelyik kiadásnál eltörhet. Ezért az extrakció kizárólag a hook által strukturáltan átadott mezőkből dolgozik.
